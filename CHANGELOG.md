# Changelog

## 0.2.0 (alpha, in progress)

- The terminal app uses TUIKit 1.13.0: the token heatmap's padding comes from `HeatMap.CellGap` instead of a custom surface, and its cells are colored by a `HeatMapPalette` built from the chosen terminal palette (empty cells in the muted color, then a ramp through the accent).
- The terminal app's token heatmap leaves one column of padding between cells.
- The terminal app has the desktop app's color palettes under Settings > Colors (chosen separately for the terminal), and Custom Colors edits the shared custom colors.
- The terminal app's token heatmap is drawn by TUIKit's HeatMap: shading levels with a Less/More legend, theme colors, and arrow-key or mouse selection that describes the selected cell.
- Web dashboards: the usage Chart list sits first in the filter row, beside Group by, Count, Model, and Provider.
- Usage: the token activity heatmap has one row per day for ranges up to a month (last day, week, or month), so a month shows a month; longer ranges keep weekday rows. The terminal app shows the newest days when the heatmap is taller than its space.
- Usage in the web dashboards (local and cloud) and the desktop app shows one chart at a time at full width, picked from a Chart list, instead of a two-column grid or tabs. The cloud dashboard's connected clients chart is in the same list.
- Web line charts join readings across empty buckets with a dashed segment and mark every reading, as the desktop app does.
- Chat: new conversations start with a built-in system prompt (set your own for new chats in Settings, or change or clear it per chat); the desktop and terminal System Prompt editors fill it in for chats that have none.
- Delete several chats at once everywhere: Select mode with checkboxes in the web dashboards, Cmd/Ctrl- or Shift-click plus Delete in the desktop app, Delete Chats in the terminal app, and `xeno chat delete <id> <id>...` (or `--all --yes`) in the CLI.
- Desktop chat shows the working folder under the title (click it to change), and Tools... opens a window listing every tool by group with a Read-only or Asks first badge and a filter.
- Desktop chat's Stop button is red with white text in every palette, light and dark.
- A client running in a terminal (`run-client`, `xeno connect --foreground`) prints only connection changes, warnings, and errors; per-message lines go to the log file, and `--verbose` prints them too. Apps started by other Xeno apps (the tray agent started by `run-client`, the desktop app started by the tray) no longer write into the terminal that started them.
- A server message the client cannot read is skipped instead of dropping the connection ("JSON could not be deserialized as WebSocketMessageEnvelope").
- Fixed: with Apple GPU telemetry the client dropped its server connection once a minute ("JSON could not be deserialized as ClientTelemetrySnapshot"), because the shared telemetry format lacked the new GPU source. The source is now shared, and a telemetry failure is reported to the server instead of ending the connection.
- Desktop line charts join readings across empty buckets with a dashed segment and mark each reading, instead of breaking into fragments; the Requests chart is taller; Provider telemetry offers only the metrics a provider reports (Ollama reports loaded and available model counts) and starts on one with data.
- macOS: opening Xeno.app (Finder, Launchpad, Spotlight, or the Dock) while the Xeno Agent runs opens the desktop app; before, the agent, which shares the bundle, took the request and nothing opened.
- GPU telemetry on Apple silicon Macs: utilization and unified memory in use, read from `ioreg` without admin rights (temperature and power still need an NVIDIA GPU).
- Providers pages (desktop and terminal) list the models a provider reports (for example `ollama list`) next to the configured ones, with a Source column. Editing a model the provider reports but `client.json` does not list opens a form that configures it, instead of "The model no longer exists."; such models have no Delete.
- Desktop: Enter sends a chat message, Shift+Enter or Ctrl+Enter adds a line, and the hint sits under the message box; the chat list's ... buttons clear the scrollbar; Usage shows one full-width chart per tab; Requests puts its filters above the chart; Logs has a time filter (also `ReadLogAsync`); Test Connection shows its result in a dialog; the Overview and Host charts are taller; Provider telemetry puts the metric chart first; Providers selects the first provider.
- Charts show the Xeno network series in the info color (purple in the Xeno palette) so it no longer matches This machine; palettes whose accent is close to the success green use purple for it.
- Tray menu: **Open Xeno Desktop** (was Open Xeno) and **Settings** (was Settings...); Chat... and Open Local Endpoint are gone, since the desktop app has both.
- Desktop chat: Stop is red while an answer is running; every conversation in the list has a ... menu and a right-click menu to rename or delete it (also F2 and Delete); the chat's own Rename and Delete buttons wrap instead of being cut off and are disabled until a chat is open.
- Desktop copy buttons show only a copy icon, with a tooltip saying what they copy.
- Fixed desktop crashes and errors: pages that are opened again or redrawn for a theme change no longer fail with "already has a visual parent" (which also left Chat history's range picker disconnected from its chart), a chart narrower than its time labels no longer crashes the app, and the Feedback table no longer errors on a row that has not loaded.

- Fixed: the access key a computer gets when you sign in had no permissions, so the apps' network model list failed with "403 OpenAI-compatible API permission denied". Sign-in now gives the key your roles in the tenant, and the TenantAdmin role for administrators. Sign in again on each computer to get a key with permissions.

- Added cross-tenant shared clients: a client owned by one tenant can be made an eligible routing target for other tenants. Sharing is a per-client `Shared` flag (default off), server-authoritative and set only by the owner tenant through `POST /api/v1/clients/{id}/sharing`; the connecting node never declares its own sharing and the value is preserved across reconnects. New tenant settings `DefaultClientShared` (seeds a client's initial shared value at first registration) and `ConsumeShared` (consumer off switch, default on) govern participation. A foreign shared client is eligible only when `Shared && Active` and the consuming tenant's `ConsumeShared` is true. `GET /api/v1/clients` returns a redacted `ClientView` projection for foreign shared clients that omits owner identity, tenant id, weight, in-flight, and max-parallel and reduces models to name plus capabilities, with an `origin` field of `tenant`, `operator`, or `third-party`; `GET /api/v1/admin/shared-clients` lists all shared clients across tenants for system admins; `GET /v1/models` marks shared-origin models `owned_by: "shared"` and `/api/tags` includes shared models; telemetry status reports `sharedEligibleClientCount`. Capacity across a shared client is first-come-first-served in v1 (owner requests are not prioritized). Added `SetClientSharingAsync`/`setClientSharing`/`set_client_sharing` to the C#, JavaScript, and Python SDKs and documented the feature across the routing, security, REST, and WebSocket references.
- Added full OpenTelemetry observability for the Xeno server: metrics, distributed traces, and logs exported over OTLP to an OpenTelemetry Collector, fanned out to Prometheus, Tempo, and Loki, and visualized in Grafana. Instrumentation covers HTTP requests, LLM relay (time to first token, streaming duration, tokens, round-trip and upstream timing, payload sizes), client connections/registrations/evictions, auth and RBAC mutations, email, ledger events, fleet host/provider telemetry, and .NET runtime/process metrics. Ships a pre-provisioned Docker stack (Collector, Prometheus, Tempo, Loki, Grafana on port 9400 with anonymous access), eight pre-built Grafana dashboards, a `Telemetry` settings block with environment overrides, a Grafana link card on the dashboard Settings page, an `OBSERVABILITY.md` guide, and a positive/negative Touchstone `Observability` test suite. The legacy `/metrics` endpoint is retained and now shares the same recording call sites.
